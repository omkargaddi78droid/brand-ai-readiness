# Deep Research Prompt — Novel & Out-of-the-Box AI Discoverability Techniques

## Objective

Conduct deep research to identify **novel, unconventional, and technically interesting methods** for auditing/improving how websites are discovered, retrieved, understood, trusted, cited, and used by AI agents and generative search systems.

The hackathon explicitly rewards **innovation over standard AI/SEO recommendations**. Therefore, do **not** simply suggest conventional checks such as robots.txt, metadata, schema.org, keyword density, headings, readability, citations, or generic "optimize for LLMs" advice.

The goal is to discover **additional capabilities, detection techniques, signals, heuristics, experiments, or implementation ideas that are meaningfully different from the capabilities we already have**.

Think like a researcher trying to find techniques that would make judges say:

> "This is an unusual but technically defensible way to detect an AI-agent/discoverability problem."

# Hard Constraints

These are non-negotiable.

### 1. No browsers

The judges run the solution in **Python/Node environments**.

Do NOT propose anything requiring:

* Playwright
* Puppeteer
* Selenium
* Chromium
* Chrome
* Crawl4AI
* headless/headerless browsers
* rendered DOM
* browser automation
* browser-based JavaScript execution

Static HTTP and parsing are allowed:

* `requests`
* `httpx`
* Node `fetch`
* raw HTML
* JSON-LD
* embedded JSON
* hydration-state blobs
* HTTP headers
* XML
* static CSS/resource inspection
* locally computed statistics/heuristics

### 2. External website querying is allowed, but narrowly

For capabilities involving:

* brand visibility
* brand presence
* mentions
* discoverability
* reputation signals
* external corroboration
* public discussion

we may directly query public websites such as:

* Reddit
* Quora
* forums
* review sites
* other publicly accessible sources

Respect `robots.txt` and use direct HTTP retrieval.

### 3. No outsourced intelligence

Do NOT use third-party APIs/services that return:

* pre-computed SEO scores
* GEO scores
* rankings
* classifications
* sentiment scores
* authority scores
* visibility scores
* AI-readiness scores
* proprietary analyses

If a signal can be computed locally from retrieved raw data, **we must compute it ourselves**.

Find signals that arise specifically because modern systems use:

* sparse retrieval

* reranking
* entity resolution
* knowledge graphs
* citation selection
* context compression
* query rewriting

Look for failure modes that ordinary SEO audits would never detect.

# Innovation Filter

For every proposed capability, score it on:

1. **Novelty** — Would a typical SEO/GEO auditor already do this?
2. **AI relevance** — Does it specifically affect retrieval, grounding, citation, synthesis, or agent usability?
3. **Implementability** — Can it be implemented in Python/Node without a browser?
4. **Evidence quality** — Can the detector produce concrete evidence rather than an opinion?
5. **False-positive safety**
6. **Computational cost**
7. **Hackathon differentiation**
8. **Potential judge "wow factor"**

Strongly prioritize ideas that are:

> **simple to implement + technically defensible + unusual + produce surprising findings.**

# Important Research Discipline

Use primary and technically authoritative sources wherever possible.

Prefer:

* academic papers
* search-engine research
* official technical documentation
* standards/specifications
* research from major search/retrieval/NLP organizations
* engineering papers/blogs with concrete technical methodology
* high-quality open-source implementations

Do not treat marketing articles claiming "AI SEO best practices" as strong evidence.

For every high-value idea, provide source evidence showing **why the underlying mechanism is plausible**, and clearly distinguish:

* established mechanism
* research-backed inference
* novel proposed adaptation
* speculative idea

The final result should feel like **technical R&D for a novel AI-web auditing system**, not a conventional SEO checklist.
